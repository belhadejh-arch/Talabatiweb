أريد إعادة تصميم نظام السائقين بالكامل وإلغاء أي نظام رسائل خارجي نهائيًا.

احذف نهائيًا:
WhatsApp/WP Sender/WhatsApp API وجميع متغيراته، Telegram/Telegram Bot/Chat ID//start/Telegram activation/Replit identity الخاص به، وجميع واجهات وإعدادات وكود هذه الأنظمة المتعلقة بإرسال الطلبات.

النظام يجب أن يعمل داخل المنصة فقط.

1. إنشاء حساب السائق
الإدارة فقط تنشئ السائق. البيانات:
الاسم الكامل، الهاتف، WhatsApp كمعلومة فقط، العنوان، تاريخ الميلاد إن كان موجودًا، الصورة، المطعم التابع له، وأي بيانات شخصية موجودة حاليًا.
أنشئ رقمًا تسلسليًا تلقائيًا فريدًا من 6 أرقام فقط مثل 645738، غير مكرر، ولا يحتاج السائق Email أو Password.

2. دخول السائق
الدخول من الرقم التسلسلي المكون من 6 أرقام فقط. لا Email/Password/WhatsApp/Telegram/Chat ID.
بعد الدخول أنشئ Session/Authentication آمنة، ولا تعتمد على الرقم وحده في API requests.

3. حساب السائق
تظهر لوحة خاصة بالسائق فيها اسمه، صورته، مطعمه وحالة حسابه.
لا يستطيع رؤية مطاعم أو بيانات سائقين آخرين أو لوحة الإدارة.

4. الطلبات الجديدة
الطلب يظهر مباشرة داخل منصة السائق مع إشعار وصوت/تنبيه مرئي.
اعرض: رقم الطلب، المطعم، نوع الطلب DELIVERY/RESERVATION، العميل، الهاتف، المنتجات، الكميات، الأسعار، الإجمالي، الملاحظات، التاريخ والوقت.
DELIVERY: الموقع، Latitude، Longitude، Google Maps وزر فتح الموقع.
RESERVATION: لا تطلب أو تعرض GPS إذا لم يكن موجودًا.

5. قبول/رفض
كل طلب يحتوي:
✅ قبول
❌ رفض
عند القبول: ACCEPTED، تسجيل السائق، إيقاف ظهوره كطلب جديد، عدم إرساله لسائق آخر وإضافته للمقبولة.
عند الرفض: REJECTED لهذا السائق، حفظه في PostgreSQL، ونقله لسائق ACTIVE آخر من نفس المطعم.

6. مهلة القبول
الافتراضي 3 دقائق وقابل للتعديل من الإعدادات: 1/2/3/5/10 دقائق.
إذا لم يقبل أو يرفض: TIMEOUT، إزالة الطلب من طلباته الجديدة، نقله لسائق ACTIVE آخر من نفس المطعم، وعدم إعادته للسائق المنتهي وقته.
الـTimer يعمل Backend وليس Frontend فقط ويستمر حتى عند إغلاق الموقع/الهاتف.

7. إحصائيات السائق
اعرض:
📦 إجمالي الطلبات
✅ المقبولة
❌ المرفوضة
⏱ الملغية/المنتهية المهلة
والمقصود بالأخيرة الطلبات التي لم يقبلها أو يرفضها خلال المهلة وانتقلت لسائق آخر، ولا تحسب الرفض اليدوي ضمنها.

8. سجل الطلبات
قسم "طلباتي" ويحتوي المقبولة، المرفوضة، والمنتهية المهلة/الملغية.
كل طلب: الرقم، المطعم، التاريخ/الوقت، العميل، التفاصيل، الإجمالي، وحالة السائق تجاهه.

9. الملف الشخصي
قسم "👤 ملفي الشخصي" يعرض الصورة، الاسم، الهاتف، WhatsApp كمعلومة فقط، العنوان، المطعم، الرقم التسلسلي، تاريخ إنشاء الحساب، والحالة.
البيانات الحساسة تتحكم بها الإدارة.

10. إشعارات المنصة
نظام Notifications حقيقي. عند وصول طلب يظهر فورًا أعلى المنصة حتى لو كان السائق في صفحة أخرى.
مثال:
🔔 طلب جديد من مطعم باريس
الطلب #1025
اضغط لعرض الطلب
والضغط ينقل لتفاصيل الطلب.

11. Push Notifications
أريد Web Push حقيقية تصل حتى خارج الموقع/عند عدم فتح الصفحة.
عند أول دخول اطلب إذن:
🔔 تفعيل إشعارات الطلبات
"اسمح بالإشعارات حتى تصلك الطلبات الجديدة فورًا حتى عندما لا تكون داخل المنصة."
استخدم Service Worker + Push API + Notifications API أو الحل الإنتاجي المناسب للـPWA.
تعمل داخل المنصة، صفحة أخرى، خارج الموقع، والمتصفح المغلق إذا كان النظام والمتصفح يدعمان ذلك.

12. Push Subscription
عند السماح احفظ Subscription في PostgreSQL مرتبطًا بـ:
driver_id، device/browser، subscription، created_at، updated_at، active.
لا تحفظ driver_id فقط لأن السائق قد يستخدم أكثر من جهاز.
عند انتهاء/إلغاء الصلاحية حدّث active عند الحاجة.

13. إرسال Push
عند الطلب:
PostgreSQL → restaurant_id → السائقون المؤهلون → محاولة توزيع → Web Push للسائق المختار → الإشعار.
الإشعار:
🚨 طلب جديد
مطعم باريس
الطلب #1025
الإجمالي: 85 د.ل
[عرض الطلب]
والضغط يفتح تفاصيل الطلب مباشرة.

14. عدم السماح بالإشعارات
لا تمنع الاستخدام، لكن اعرض:
⚠️ إشعارات الطلبات غير مفعلة
فعّل الإشعارات حتى لا تفوتك الطلبات.

15. قاعدة البيانات
PostgreSQL حقيقي، وأضف/عدّل:
drivers
driver_push_subscriptions
orders
order_driver_attempts
notifications
مع ربط driver_id وrestaurant_id وorder_id.
لا Mock Data.

16. توزيع الطلبات
طلب جديد → المطعم → السائقون التابعون له → ACTIVE → Push + الطلب داخل المنصة → قبول/رفض.
رفض → التالي.
TIMEOUT → التالي.
قبول → تثبيت الطلب.
لا ترسل لمطعم آخر، ولا لسائق غير ACTIVE، ولا ترسل الطلب لجميع السائقين في نفس الوقت.

17. الأمان
الرقم التسلسلي يستخدم فقط لبدء الدخول، ثم Session/Token آمن.
كل API يتحقق من:
driver_id + authentication session + restaurant permissions
لمنع الوصول لحساب أو بيانات سائق آخر.

18. التصميم
Mobile First.
الصفحة الرئيسية تركز على:
🔔 الطلبات الجديدة
📦 طلباتي
📊 إحصائياتي
👤 ملفي
والطلب الجديد يكون واضحًا جدًا وسريع القبول/الرفض.

19. مهم
لا تحذف الطلبات القديمة أو تاريخ السائق أو الإحصائيات.
لا localStorage كقاعدة بيانات.
لا Mock Data.
كل شيء من PostgreSQL.
نفذ Backend + PostgreSQL + Frontend + Service Worker + Web Push.
اختبر إنشاء السائق، رقم 6 أرقام، الدخول، المطعم الصحيح، الطلب، الإشعارات، Push خارج الموقع، القبول، الرفض، انتهاء المهلة، الانتقال للسائق التالي، الإحصائيات، السجل والملف الشخصي.
لا WhatsApp ولا Telegram لإشعارات الطلبات.

أنشئ رابطًا مستقلًا عن الأدمن:
https://yourdomain.com/driver/login
صفحة:
🚚 دخول السائق
[ الرقم التسلسلي 6 أرقام ]
[ دخول ]
لا يظهر دخول الأدمن.
بعد الدخول:

احمِ صفحات/API السائق بـSession/Authentication.
السائق لا يصل للأدمن، والأدمن لا يحصل على صلاحيات السائق إلا حسب الصلاحيات.
رابط واحد ثابت لجميع السائقين، وليس رابطًا منفصلًا لكل سائق.
أضف تسجيل الخروج وإبطال Session.
كل سائق يرى حسابه ومطعمه وطلباته وإحصائياته وملفه فقط.
